Definitions and limits

Methodology

Deterministic comparisons of bounded public metadata, with incomplete sources kept visibly incomplete.

What is observed

DistWitness uses PyPI's JSON Index API to select the highest eligible PEP 440 version, retrieves compact metadata from the documented release-specific JSON endpoint, asks PyPI for per-file reported provenance, and asks OSV about the exact selected package version.

What a change means

A change means that two normalised observations differed. Informational, review, and urgent labels prioritise human attention; they are not probability estimates or security scores.

Incomplete data

Absent, unsupported, unavailable, failed, and malformed provenance responses remain distinct. An incomplete OSV response cannot create an advisory-removal event. Stale retained data stays visible when a fresh value cannot be verified.

What is not established

DistWitness does not download, install, import, unpack, execute, or scan package code. It cannot establish that a package is safe, malicious, trustworthy, compromised, or suitable for a particular use.

Sources

Release discovery comes from PyPI's documented Index API. Selected-release and file metadata come from PyPI's documented release-specific JSON and Integrity APIs. Advisory identifiers and bounded metadata come from OSV. Each finding links to an authoritative record; no third-party advisory body text is mirrored.

Evidence-backed release metadata changes. Review signals, not verdicts.
